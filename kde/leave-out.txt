# Packages the wasm32 KDE image leaves out in both forms, ours and Debian's
# (mkrootfs.py --leave-out): what depends on them is installed without them,
# the clause dropped from its Depends in the image's status file.
#   PACKAGE | why | what is lost
#
# udisks2 and what only it pulls: libblockdev's plugins, cryptsetup,
# parted, libnvme, lvm2's libdevmapper and dmsetup, volume_key with NSS
# and the GnuPG programs under gpgme
udisks2        | a page has no block devices to manage | VISIBLE: Dolphin's Devices panel and Plasma's disk and device notifier list no drives
libudisks2-0   | as above | as above
# the browser runs the page's own Xwayland, never the tree's
xwayland       | only kwin-wayland pulls it (the X11 session runs the page's X server) | the Plasma Wayland session's X11 support (that session is not run)
# glibc's tools: our programs are on musl, whose loader keeps no cache
libc-bin       | Debian's is glibc's arm64 ldconfig, getent, locale and iconv, and pulls glibc itself (libc6, libgcc-s1); musl's loader reads no ld.so.cache | the locale, iconv and getconf commands (getent is a script over the files, mkrootfs.py); a library apt installs later runs no ldconfig (nothing needs one)
# not built for wasm32 yet: what names them is installed, so apt sees an
# image whose every Depends is met (it refuses any install otherwise)
python3.13           | not built for wasm32 yet | python3 (the python3 packages are only what the image's tools name)
python3.13-minimal   | as above | as above
libpython3.13-stdlib | as above | as above
python3              | as above: ours without python3.13 is no interpreter, and held it would keep Debian's arm64 python3 out | nothing (Debian's arm64 python3 installs when something asks for it)
python3-minimal      | as above | as above
libpython3-stdlib    | as above | as above
cpp                  | GCC's preprocessor is GCC itself (cc1), and GCC has no wasm32-hosted build | Plasma's colours and fonts in X resources for non-Qt X programs (krdb's xrdb -merge runs cpp; the font settings' xrdb -nocpp still work)
gdb                  | gdb debugs through ptrace, which gex does not have | gdb
drkonqi              | Plasma's crash reporter gets its backtrace by attaching gdb (ptrace, which gex does not have) | the crash dialog after a program dies
libpipewire-0.3-0t64 | no PipeWire daemon in a page (no audio or screen capture service) | Qt Multimedia's PipeWire backend
qml6-module-org-kde-pipewire | as above | screencast thumbnails in the task manager
# two packages of one role, both pulled by the closure: one is left out
sudo-ldap            | sudo is in the image; the two conflict | sudo with an LDAP sudoers source
systemd-standalone-sysusers | systemd in the image provides systemd-sysusers, which this conflicts with | nothing (the same program)
